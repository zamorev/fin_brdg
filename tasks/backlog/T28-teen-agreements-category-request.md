# T28 — Подросток видит свои категории и просит изменить одну

## Description

Сейчас кнопка «Мои договорённости» на главной подростка ведёт обратно на главную (`onOpenAgreements={goHome}` в `App.tsx`). Нужен экран, где подросток видит свой бюджет недели и все категории с суммами — как родитель на экране подростка (T20, `TeenAgreement.tsx`). Там же он может изменить сумму одной категории, но изменение **не применяется сразу**: уходит родителю запросом, родитель решает на экране «Запросы».

Решение владельца (2026-11-01, записать в [parent-screens.md](../../docs/design-docs/parent-screens.md) как **D12**): перераспределение по категориям подросток делает **через запрос родителю**, даже если деньги берутся из резерва. Это осознанное отступление от Н4 в том же документе: там предлагалось не требовать разрешения на перекладку внутри бюджета.

### Как устроено

**Экран `MyAgreements` (подросток):**

- шапка: «‹ Главная» + Telegram BackButton → главная;
- карточка «Бюджет на неделю»: сумма, полоса распределения, строка статуса («Распределено всё» / «Не распределено» / перебор). Без кнопок −/+: бюджет подросток просит через «Попросить больше» (T20);
- список 5 категорий: сумма из плана крупно, «мин. N ₽» / «без минимума» мелко — те же блоки, что у родителя (вынести общие компоненты из `TeenAgreement.tsx`, не копировать);
- если есть запрос в `pending` — баннер «Ждём ответа семьи: {что просил}» → экран статуса запроса; отправка нового запроса недоступна (одно ожидающее решение на семью, как сейчас в `createRequest`);
- тап по категории → шторка `CategorySheet` в **режиме запроса**.

**Шторка в режиме запроса** (тот же компонент, новый режим):

- степпер, чипы, минимум, блок «Откуда взять» (резерв / увеличить бюджет) и «Освободится N ₽ — уйдут в резерв» — как у родителя (`changeCategory`);
- обязательное поле «Зачем» (как в «Попросить больше»);
- кнопка «Отправить родителю» вместо «Сохранить»; при отправке ничего в договорённости не меняется;
- после отправки — существующий экран `RequestSent` («Показали родителю») с кнопкой «Готово» → главная.

**Новый вид запроса `category_change`** (поле `category` в `RequestDoc` как дискриминатор, рядом с `weekly_budget` и старым `entertainment`):

- поля: `categoryKey`, `currentAmount` / `proposedAmount` — сумма категории, `fundingSource: "reserve" | "budget"`, `teenTelegramId`, `explanation`;
- проверка в домене (обе копии): сумма ≠ текущей, кратна 50, не ниже минимума категории, объяснение обязательно; если источник «бюджет» — прибавка к бюджету не больше `BUDGET_INCREASE_MAX`;
- `changeCategory` и `reserveSpare` перенести и в `functions/src/domain.ts` (сейчас только во фронте) — одобрение применяет ту же функцию на сервере.

**Родитель (`ParentRequests`):**

- карточка запроса по категории: «Развлечения: 400 → 500 ₽», «Почему», последствия из `changeCategory` («резерв 200 → 100 ₽» или «бюджет 1 600 → 1 700 ₽»);
- «Одобрить» → сервер применяет `changeCategory` к **текущей** договорённости (лимиты могли поменяться после запроса); «Своя сумма» — та же шторка/степпер по сумме категории; «Отклонить» и «Расскажи ещё» — как сейчас;
- «Недавно решено», баннер на экране подростка у родителя и подпись на главной родителя понимают новый вид.

**Главная подростка и статус:** строка запроса и `RequestStatusTeen` показывают «{Категория}: X → Y ₽»; после одобрения — новые суммы.
