# T24 — Приёмка по Definition of Done

## Description

Финальная проверка прототипа по [PRODUCT.md → DoD](../../docs/PRODUCT.md#definition-of-done-dod) в настоящем Telegram, с двух аккаунтов, на prod `https://fin-brdg.web.app` через @fin_brdg_bot. Итог — чеклист с отметками, демо-данные, запись экрана, список найденных багов отдельными задачами.

Аналог из v1: [archive/T10](../archive/T10-e2e-smoke.md).

## Acceptance Criteria

- [ ] `docs/DEMO.md`: чеклист DoD (5 шагов сквозного сценария + «Качество перед демо»), сценарий демо на 2 минуты, кто какой аккаунт
- [ ] Деплой актуального `main` владельцем проекта (`./scripts/deploy-v2.sh`) — версия фронта (`id …` внизу главной родителя) совпадает с собранной из `main`
- [ ] Сквозной сценарий с **двух Telegram-аккаунтов**, всё кликами:
  - [ ] 1. Подросток: «Неделя на 1 500 ₽», ошибки суммы и минимумов, успех сохранён
  - [ ] 2. «Незапланированная покупка»: 4 варианта, последствия и дефицит
  - [ ] 3. Запрос с суммой и объяснением; статус «Ждём ответа» у обоих
  - [ ] 4. Родитель видит правила, результаты квестов, навыки, запрос; решает с комментарием (одобрить / отклонить / уточнить)
  - [ ] 5. Подросток видит статус и комментарий; при одобрении новые правила у обоих
- [ ] После перезагрузки Mini App у обоих данные совпадают
- [ ] Граничные значения вручную: сумма 1 499 / 1 500 / 1 501, минимум −1 / ровно, запрос 0 / 1 500 / 1 501 / равный текущему
- [ ] Сценарий «Ой, кино»: напоминание бота пришло, шаг открывается по кнопке
- [ ] Демо-семья подготовлена (без личных данных), запись экрана сохранена (ссылка в `DEMO.md`)
- [ ] Найденные дефекты — задачи в `tasks/backlog/` (критические — исправлены до демо)

## Notes

- Только Telegram: эмулятор не покрывает MainButton/BackButton, бота и scheduler.
- Не входит в DoD (после демо): рост уровня/XP (сейчас всегда «3 уровень, 140 XP»), миграция квеста 2 на движок сценариев (фаза E T17), одна копия домена (X7).
