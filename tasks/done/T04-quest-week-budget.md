## Description

## Acceptance Criteria

- [x] Сумма строго 1 500 ₽

- [x] Понятные ошибки на русском
- [x] Успех сохраняет результат квеста для отображения родителю (минимум session_state)

## Notes

Согласовано с T02; не менять константы здесь.

## Result

- `src/quests/week_budget.py` — сценарий квеста без Streamlit: `starting_allocation()` (минимумы из правил, развлечения 0 → 1 100 ₽, свободно 400 ₽), `remaining()`, `slider_scale()` (общая шкала 0 – недельный бюджет), `clamp_amount()` (не ниже минимума категории, у развлечений — 0), `check_week_budget()` (значения формы → `BudgetAllocation` → `validate_allocation`) → `QuestResult`, `save_result()` (при успехе `week_budget_quest_completed = True` и `quest_1_allocation` в `st.session_state`; неудача прежний успех не стирает).
- `app/pages/teen_quest_week.py` — экран по макету: «← Квест 1 из 1», ползунок на каждую категорию (шаг 50 ₽, подписи `Category.label`, суммы `format_rub`), «Распределено X из 1 500 ₽» (жёлтый — недобор, зелёный — ровно, красный — перебор) + «Осталось распределить / Перебор / Всё распределено», «Проверить мой бюджет». Ошибки — тексты `BudgetError.message`; успех — «Квест пройден!». Чисел бюджета в файле нет, всё из `DEFAULT_RULES`.
- `teen_home.py`: заглушка квеста заменена экраном; после прохождения подзаголовок строки — «Пройден — план сохранён».
- `DEFAULT_ALLOCATION` в квесте не используется: старт — минимумы, а не готовый план. `src/domain` не менялся.
- Тесты: `tests/test_quest_week_budget.py` — логика квеста и экран через `streamlit.testing.v1.AppTest`; доменные проверки из `test_domain.py` не дублируются.
- Все ползунки на шкале 0 – 1 500 ₽, бегунок стоит по своей сумме; попытка увести ниже минимума возвращает бегунок на минимум (`on_change` → `clamp_amount`).
