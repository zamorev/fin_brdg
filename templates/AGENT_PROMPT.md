# Инструкции агента (Fin Bridge / fin_brdg)

Ты участник команды хакатона. Работай по репозиторию `fin_brdg`.

## Обязательно прочитать

1. `AGENTS.md` — карта (далее только нужные файлы из `docs/index.md`)
2. `docs/PRODUCT.md` — MVP и сценарии
3. Свою задачу в `tasks/in-progress/` — acceptance criteria и `owns:`
4. `docs/design-docs/core-beliefs.md` — при спорных решениях

## Фокус

- Выполняй **только** назначенную задачу.
- Не расширяй MVP (см. «Что не входит в MVP» в `docs/PRODUCT.md`).
- Стек: **TypeScript** — Mini App `v2/web` (React, Vite), API `functions/` (Firebase Functions), Firestore; суммы условные; без банковской интеграции.

## Координация

1. Ветка: `agent/<ник>/<task-id>` (как в frontmatter задачи).
2. Коммиты: `<TASK_ID>: описание`.
3. Соблюдай `harness/OWNERSHIP.md`; не рефактори чужие зоны.
4. Общие файлы — минимальные правки.

## Качество

- Логика бюджета и проверок — в `functions/src/domain.ts`, данные — в `functions/`, UI — в `v2/web`.
- Перед завершением: `./scripts/verify.sh` и smoke на эмуляторах (`docs/LOCAL_DEV.md`), пройти acceptance criteria.
- Не коммить секреты, `.env`, `functions/.env`.

## Ретро по коммитам

После шага работы или перед PR: проанализируй **последние 1–2 коммита** (`git log -2`, `git show`) и предложи улучшения по чеклисту в `harness/COORDINATION.md` (раздел «Ретро по последним коммитам»). Правки по ретро — только по явному запросу, кроме блокеров verify/ownership.

## Готово, когда

- Все пункты acceptance criteria отмечены в файле задачи
- Приложение запускается
- Изменения закоммичены в свою ветку
- Краткое ретро по последним коммитам дано (или обновлено перед PR)
- Задача перенесена в `tasks/done/` после merge (или PR открыт)

## Если заблокирован

- Зависимость от другой задачи — зафиксируй в комментарии к задаче, не дублируй контракты в UI.
- Неясность по продукту — следуй `docs/PRODUCT.md`, не выдумывай новые фичи.
