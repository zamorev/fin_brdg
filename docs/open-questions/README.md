# Открытые вопросы на будущее

Вопросы **вне текущего MVP**: не блокируют ближайшие задачи, но их стоит зафиксировать, чтобы не потерять при планировании следующих итераций.

Не путать с:

- решениями в [design-docs](../design-docs/index.md) (принятые инварианты);
- задачами в [tasks](../../tasks/README.md) (есть acceptance criteria и владелец).

## Когда добавлять

- После интервью, питча, обсуждения в чате — если ответа нет, но тема важна.
- Перед расширением продукта за рамки [PRODUCT.md](../PRODUCT.md) — проверить, не закрыт ли вопрос уже здесь.

## Формат записи

Один вопрос — файл `OQ-NNN-<kebab-topic>.md` в этой папке.

### Frontmatter (YAML)

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `id` | да | `OQ-001`, `OQ-002`, … |
| `title` | да | Короткое название (одна строка) |
| `status` | да | `open` \| `parked` \| `resolved` |
| `area` | да | Зона продукта: `onboarding`, `trust`, `family-link`, `bot`, … |
| `raised-by` | нет | Кто поднял тему |
| `raised-at` | нет | Дата (ISO `YYYY-MM-DD`) |
| `related` | нет | Ссылки на docs, задачи, ADR |

### Секции в теле

1. **Вопрос** — одна формулировка, на которую ищем ответ.
2. **Контекст** — цитата или факт из обсуждения (опционально).
3. **Заметки** — гипотезы, trade-off, что пробовали (опционально).
4. **Решение** — только при `status: resolved` (дата, итог, ссылка на ADR/PRODUCT).
