## Проблема 1 — ползунок трудно поймать

Разбор (браузер + известное поведение WebView):

- Нативный `<input type="range">` без стилей: бегунок ~16–20 px, дорожка 4 px — пальцем легко промахнуться.
- iOS WebKit (Telegram iOS): тап по дорожке **не переносит** бегунок, двигать можно только начав с бегунка. Это и даёт «надо попасть точно / нажать дважды».
- Android WebView: тап по дорожке работает, но маленькая зона касания и вертикальный жест может уйти в прокрутку.

Решение:

- Свои стили дорожки и бегунка (`-webkit-` / `-moz-`): бегунок 28 px, дорожка 8 px, зона касания по высоте 36 px.
- Касания обрабатываем сами (pointer events на обёртке, `touch-action: none`, `setPointerCapture`): значение считается по координате пальца — тап по дорожке переносит бегунок, движение сразу двигает. Сам `<input>` остаётся для клавиатуры и экранного диктора (`pointer-events: none` только для мыши/пальца).
- Проверка пальцем в Telegram iOS и Android — **владелец после деплоя** (локально проверяется браузер и мобильная эмуляция).

## Проблема 2 — кнопка «выезжает» после каждого изменения

Причина: новый `onClick` на каждый рендер → эффект `MainAction` прячет MainButton и показывает через 450 мс.

Решение в `MainAction.tsx` (работает для всех экранов):

- `onClick` хранится в ref; в MainButton уходит стабильная обёртка → эффект регистрации зависит только от `text`, `visible`.
- `enabled` обновляется отдельным эффектом (`setMainButton({ enabled })`) без hide/show и без нового 450 мс таймера.
- Guard 450 мс (`MainAction`) и 500 мс (`TwaProvider`) сохранены — при первом показе экрана.

`QuestBudget` передаёт `enabled` всегда `true`; повторное нажатие во время запроса игнорируется внутри `onCheck`.

Риски для других экранов (`NewConditions`, `ParentRequest`, `ScenarioStep`, `RequestSent`, `OnboardingScreen`, `Consequences`, `UnplannedPurchase`, `RequestStatusTeen`): раньше смена `onClick` давала «свежий» обработчик с перерегистрацией — теперь ref всегда указывает на последний `onClick`, поведение то же. Смена `enabled` (например, `!submitting`) больше не прячет кнопку — это улучшение. `TwaProvider` не меняется.

## Проблема 3 — ниже минимума

- Шкала у всех категорий 0 – недельный бюджет, шаг 50 ₽.
- Любое новое значение (палец, клавиатура) зажимается: `Math.max(value, CATEGORY_MINIMUMS[key] ?? 0)` — хелпер в экране, домен не трогаем.
- «Развлечения» — минимума нет → от 0.
