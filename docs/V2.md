## Локальная разработка

**Лаунчер (macOS):** двойной клик по [`scripts/Launch v2 Dev.command`](../scripts/Launch%20v2%20Dev.command) — эмулятор API, Vite, браузер на `http://localhost:5173`. Или из корня: `npm run dev:v2`.

Нужен `functions/.env` с **`AUTH_SKIP=1`** (см. `functions/.env.example`).

**Терминал 1 — API (обязательно для localhost):**

```bash
cd functions && npm install && npm run build
cd ..
# functions/.env: TELEGRAM_BOT_TOKEN=… и AUTH_SKIP=1 (см. functions/.env.example)
npx firebase emulators:start --only functions,firestore --project demo-fin-brdg
```

⚠️ Всегда с **`--project demo-fin-brdg`**: без флага CLI берёт боевой `fin-brdg` из `.firebaserc` (Vite не найдёт API, запись в Firestore может уйти в prod). Подробно — [LOCAL_DEV.md](LOCAL_DEV.md).

**Терминал 2 — UI:**

```bash
cd v2/web && npm install && npm run dev
# http://localhost:5173 — Vite проксирует /api → эмулятор (europe-west1)
```

Без Telegram в браузере работает только связка **эмулятор + `AUTH_SKIP=1`**. Иначе открой Mini App через бота (`https://fin-brdg.web.app`).

Полный стек с Hosting-статикой (`dist/` не в git — сначала собрать):

```bash
npm --prefix v2/web run build
npx firebase emulators:start --only hosting,functions,firestore --project demo-fin-brdg
```

## Модель аккаунтов

**1 Telegram = 1 пользователь.** Переключателя ролей в приложении нет.

| Коллекция | Смысл |
|-----------|--------|
| `users/{telegramId}` | Профиль; см. **`userType`** ниже |
| `families/{id}` | Бюджет, квесты, invite-токены |
| `requests` | Запросы подростка, решения родителя |
| `scenarioRuns/{id}` | Прохождение сценарного квеста (подросток, узел, таймер) |

В семье может быть несколько родителей и подростков. Старые `members/*` читаются для совместимости.

### `users/{telegramId}` (T12)

| Поле | До онбординга | После онбординга |
|------|----------------|------------------|
| `userType` | **`anonymous`** | `teen` \| `parent` |
| `familyId` | нет | обязателен |
| `displayName` | из Telegram | обновляется |
| `photoUrl` / `photoFilePath` | опционально | кеш фото для `/api/avatar` |
| `createdAt` | при первом `/api/me` | сохраняется |

- **`ensureUserRecord`** вызывается из `buildMe`, `completeOnboarding`, `joinByInviteCode`.
- **`isOnboardedUser`**: не `anonymous` и есть `familyId` → полная сессия; иначе `needsOnboarding: true`.
- Anonymous **не** попадает в `GET /api/family` → списки участников.

### Онбординг

| Сценарий | Поведение |
|----------|-----------|
| **Invite-ссылка** | `start_param` в initData → **`GET /api/me` сам вызывает join** (T12+); иначе клиент «Приглашение в семью» |
| **Первый без ссылки** | «Кто ты» → «Создать семью» → `POST /api/onboarding` `{ userType, mode: "create" }` |
| Повторный вход | `GET /api/me` — сессия без онбординга |

Ручного ввода кодов в UI **нет**.

### Приглашения (ссылки)

- Firestore: **`inviteCodeParent`**, **`inviteCodeTeen`** (lazy migration в `getFamily`).
- UI: только **«Отправить ссылку»** на «Семья» (`FamilyScreen.tsx`, `botInviteLink` в `v2/web/src/telegram/bot.ts`).

**Формат ссылки (актуальный, T12+):**

```text
https://t.me/fin_brdg_bot?start=inv_t_<TEEN_TOKEN>
https://t.me/fin_brdg_bot?start=inv_p_<PARENT_TOKEN>
```

**Почему так:** ссылка открывает **чат бота** и шлёт `/start inv_…`. Webhook сохраняет invite в **`pendingInvites/{telegramId}`**. Пользователь жмёт «Fin Bridge» внизу (Menu) — `GET /api/me` подхватывает pending и вступает в семью **без** `start_param` в Mini App.

Webhook: `./scripts/set-telegram-webhook.sh` → `https://fin-brdg.web.app/api/telegram/webhook` (после деплоя Functions).

Дополнительно: `startapp=t_…` / `start_param` в initData — если Mini App открылся напрямую.

API:

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/api/me` | сессия или `needsOnboarding` (+ создаёт `anonymous`) |
| POST | `/api/onboarding/join-invite` | `{ code }` — param с `t_`/`p_` или голый токен |
| POST | `/api/onboarding` | create (и join для API) |
| GET | `/api/invite-preview?code=` | роль по коду |
| GET | `/api/family` | участники (без anonymous) |
| GET | `/api/avatar/:telegramId` | фото участника семьи (Authorization: `tma …`) |
| POST | `/api/scenarios/:scenarioId/start` | подросток — начать сценарный квест |
| POST | `/api/scenarios/runs/:runId/answer` | подросток — ответ на шаг `{ optionId }` |

Сценарии: [product-specs/scenario-quests.md](product-specs/scenario-quests.md). Scheduler `scenarioStepScheduler` — pending → ready + сообщение бота.

## Аватарки (T12)

- При `/api/me` и `/api/family` — фоновое **`syncUserProfilePhoto`** / `refreshFamilyPhotos` (Bot API `getUserProfilePhotos`, опционально `photo_url` из initData).
- Клиент: `MemberAvatar` — прямой `photoUrl` или fetch `/api/avatar/:id` → blob URL.
- Токен бота **не** отдаётся в URL файла Telegram.

## Экраны

- **Подросток:** `TeenHome` → квесты → запрос (`App.tsx`).
- **Родитель:** home + «Семья» + `ParentRequest` при pending.
- **«Fin Bridge / Семья»:** invite-ряды, списки, **`MainAction` «Готово»** → home (Back с debounce).

## TWA-поведение

- Тема, safe area — `TwaProvider.tsx`; при `ready()` — **`captureInviteFromTwa`**.
- **MainButton** — квесты, «Готово» на «Семья»; не скрывать «Готово» через CSS `.btn-primary-fallback` без MainButton.
- **BackButton** — `useBackAction(handler, delayMs)`; на «Семья» явный `onDone` без debounce guard.
- **Hosting:** `index.html` — `no-cache`; `APP_BUILD_ID` — `scripts/app-build-id.sh`.

## Деплой

| Что менялось | Команда |
|--------------|---------|
| Только `v2/web` | `./scripts/deploy-firebase-hosting.sh` |
| `functions/`, invite, users, avatar | **`./scripts/deploy-v2.sh`** |

Blaze — для Functions. `TELEGRAM_BOT_TOKEN` в `functions/.env` / Secret Manager.

**Firebase CLI (один раз или после «credentials are no longer valid»):** глобальный `firebase` не обязателен. Из **корня репо**:

```bash
npm install
npx firebase login --reauth
```

Деплой всегда через `./scripts/deploy-v2.sh` — он берёт CLI из `node_modules/.bin/firebase`.

Скрипты собирают `v2/web/dist` и `functions/lib` заново из текущих исходников; в git сборки нет (T23), коммитить её после деплоя не нужно. В prod уходит то, что лежит на диске, поэтому деплой — из свежего чистого `main` (`git pull`, пустой `git status`).

BotFather: Menu Button → **`https://fin-brdg.web.app`**. См. [TELEGRAM_BOT.md](TELEGRAM_BOT.md), [FIREBASE_HOSTING.md](FIREBASE_HOSTING.md).
