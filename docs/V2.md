# Fin Bridge v2 — TWA + Firebase

Альтернатива Streamlit-прототипу: **React SPA** в Telegram Web App, **Firestore + Cloud Functions** (без SQLite в v2).

Дизайн: [`design/v2/`](../design/v2/).

## Стек

| Слой | Путь |
|------|------|
| UI (TWA) | `v2/web/` — Vite, React, Telegram WebApp SDK |
| API | `functions/` — Express на Cloud Functions `api` (region `europe-west1`) |
| Данные | Firestore: `users`, `families`, `requests` |
| Hosting | `v2/web/dist` → `https://fin-brdg.web.app`, `/api/**` → Functions |

## Локальная разработка

```bash
# фронт
cd v2/web && npm install && npm run dev

# эмуляторы (из корня репо, после npm install в functions)
cd functions && npm install && npm run build
cd ..
firebase emulators:start --only hosting,functions,firestore
```

Эмулятор Functions: задайте в `functions/.env` (не коммитить):

```bash
TELEGRAM_BOT_TOKEN=...   # тот же, что у @fin_brdg_bot
AUTH_SKIP=1              # только для эмулятора: не проверять hash initData
FUNCTIONS_EMULATOR=true
```

## Модель аккаунтов

**1 Telegram = 1 пользователь.** Переключателя ролей в приложении нет.

| Коллекция | Смысл |
|-----------|--------|
| `users/{telegramId}` | Участник: **`userType`** `teen` \| `parent`, **`familyId`** |
| `families/{id}` | Общий бюджет, квесты, **`inviteCode`** |
| `requests` | Запросы подростка, решения родителя |

В семье может быть **несколько родителей и подростков** (например 2+2). Участники — все `users` с одним `familyId`. Лимита 1+1 нет.

**Первый вход:** роль → **создать семью** или **войти по коду** → `POST /api/onboarding` `{ userType, mode, inviteCode? }`.

Экран **«Семья»**: участники по ролям и код приглашения для новых Telegram-аккаунтов.

Повторный вход: `GET /api/me` — профиль и список `members`, без выбора роли.

Старые `members/*` читаются для совместимости.

## Деплой

**Cloud Functions требуют тариф Blaze** (pay-as-you-go) в Firebase. Без него деплоят только фронт:

```bash
cd v2/web && npm ci && npm run build
firebase deploy --project fin-brdg --only hosting
```

Полный стек (API + Firestore rules):

```bash
./scripts/deploy-v2.sh
```

После перехода на Blaze:

```bash
cp functions/.env.example functions/.env   # вставьте TELEGRAM_BOT_TOKEN бота
./scripts/deploy-v2.sh
```

Секрет бота для проверки `initData` на Functions:

```bash
firebase functions:config:set telegram.token="YOUR_BOT_TOKEN"
# или для v2 env (рекомендуется):
firebase functions:secrets:set TELEGRAM_BOT_TOKEN
```

После деплоя в Google Cloud Console → Cloud Functions → `api` → переменная окружения `TELEGRAM_BOT_TOKEN` (если secrets не настроены — добавьте вручную для MVP).

BotFather: Main App / Menu Button → **`https://fin-brdg.web.app`** (тот же URL, контент теперь v2 после деплоя).

## TWA-поведение

- Тема из `Telegram.WebApp.themeParams`, safe area, `expand()`, `disableVerticalSwipes`
- **MainButton** — основные действия («Проверить бюджет», «Отправить родителю»)
- **BackButton** — стек экранов
- **HapticFeedback** на успех/ошибку
- Без переключателя роли: тип аккаунта **`userType`** в `users/{telegramId}`, онбординг один раз

## Сценарий экранов (подросток)

Главная → квест бюджета → незапланированная покупка → последствия → новые условия → запрос отправлен → статус.

Родитель: экран «Запрос подростка», когда есть `pending` request.

## Параллельность с v1

Streamlit + SQLite в `app/` и `src/` **не трогаем** — v2 живёт отдельно. Общая продуктовая логика чисел совпадает с `src/domain/constants.py`.
