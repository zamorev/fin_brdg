# Сценарии доменных тестов (наследие v1)

Сохранено из Python-тестов v1 перед их удалением (T15): `tests/test_domain.py`, `tests/test_quest_week_budget.py` (65 тестов, Streamlit + pytest). Код v1 — в истории git до коммита T15.

**Зачем:** готовый список кейсов для TS-тестов (Vitest) на `functions/src/domain.ts` и `v2/web/src/domain/budget.ts`. Числа — из [PRODUCT.md](../PRODUCT.md).

Обозначения: план по умолчанию `D` = транспорт 300, обеды 500, развлечения 400, накопления 200, резерв 100 (сумма 1 500). `D(entertainment=0)` — тот же план с одной заменой.

## 1. Константы

| # | Проверка | Ожидание |
|---|----------|----------|
| C1 | Недельный бюджет | 1 500 |
| C2 | Категории | ровно `transport`, `food`, `entertainment`, `savings`, `reserve` |
| C3 | Подписи | Транспорт, Обеды и перекусы, Развлечения, Накопления, Резерв |
| C4 | План по умолчанию (старт договорённости) | `D` |
| C5 | Минимумы | транспорт 300, обеды 500, накопления 200, резерв 100; у развлечений минимума **нет** |
| C6 | Обязательные расходы | транспорт + обеды, минимум 800 = сумма их минимумов |
| C7 | Формат суммы | `1500` → «1 500 ₽» |

## 3. Квест 1 «Неделя на 1 500 ₽»

| # | Проверка | Ожидание |
|---|----------|----------|
| Q1 | Стартовый план | категории с минимумом = минимум, развлечения = 0; свободно 400 |
| Q2 | Старт сразу «Проверить» | не пройдено (не распределены 400) |
| Q3 | Старт при других правилах (бюджет 2 000, обеды ≥ 700) | обеды 700 |
| Q4 | Остаток при `D(entertainment=500)` | −100 (перебор) |
| Q5 | Шкала ползунков | от 0 до 1 500, общая для всех категорий |
| Q6 | Ползунок категории с минимумом в 0 или ниже минимума | возвращается к минимуму |
| Q7 | Ползунок развлечений в 0 | остаётся 0 |
| Q8 | Пройдены: `D`; `D(entertainment=0, savings=600)`; `D(entertainment=100, reserve=200, food=700)` | пройдено, ошибок нет |
| Q9 | Успешная попытка | результат сохраняется для родителя |
| Q10 | Неуспешная попытка | ничего не сохраняет; ранее сохранённый успех не стирается |

UI-проверки v1 (на экране квеста): индикатор суммы «меньше / ровно / больше» (развлечения 0 / 400 / 600), смена остатка при движении ползунка (развлечения 250 → свободно 150), русские тексты ошибок домена, кнопка «Назад» → главная, на экране нет захардкоженных чисел бюджета.

## 4. Запрос на изменение правил

Базовый запрос: развлечения, сейчас 400, предлагается 500, объяснение «Хочу ходить в кино».

| # | Вход | Ожидание |
|---|------|----------|
| R1 | Базовый | ошибок нет; статус `pending`; `delta` = 100 |
| R2 | Объяснение с пробелами по краям | сохраняется обрезанным |
| R3 | Объяснение `""` или `"   "` | ошибка про объяснение |
| R4 | Предложено 0 или −50 | ошибка «больше нуля» |
| R5 | Предложено 400 (= текущей) | ошибка «должна отличаться» |
| R6 | Предложено 1 501 | ошибка «не больше 1 500» |
| R7 | Статусы | `pending`, `approved`, `rejected`, `needs_clarification` |

## 5. Решение родителя

| # | Вход | Ожидание |
|---|------|----------|
| P1 | `approved` / `rejected` / `needs_clarification` с комментарием «  Давай попробуем месяц  » | статус установлен, комментарий обрезан |
| P2 | Решение `pending` | ошибка |
| P3 | Изменить уже `approved` или `rejected` | ошибка (решение окончательное) |
| P4 | `needs_clarification` → затем `approved` | разрешено (уточнение не окончательное) |
| P5 | Применить к правилам неодобренный запрос | ошибка, правила не меняются |
| P6 | Применить одобренный запрос | сумма категории в договорённости = предложенной (развлечения 500) |
